# 眼维数据集 · 数据字典 v2.0

> 版本：v2.0（取代 v0.5.0 数据字典）｜ 编制：管道通（数据工程）｜ 日期：2026-10-13
> 定位：**数据契约（Data Contract）**，不是字段说明文档。每个字段都有类型、可空性、值域和强制质量规则。
> 实施约束：所有表必须可由 Bronze 层数据**幂等重建**（重跑结果完全一致）。

---

## 0. 分层契约（Bronze / Silver / Gold）

v0.6 的目录是"按文件类型分堆"（图像/文本/标注/配对），这是**没有分层的**——原始数据、派生数据、评测数据混在一起，任何规则改动都要全量重跑。v2.0 改为三层：

| 层 | 目录 | 内容 | 写入模式 | 消费者 |
|---|---|---|---|---|
| **Bronze** | `bronze/` | 原始下载件：IDRiD 官方图像/掩膜/分级 CSV、公开数据集原始包、外部报告文本 | **只追加，永不修改** | 仅 Silver 构建脚本 |
| **Silver** | `silver/` | 清洗、去重、对齐、按 ICDR 标准化的病例级资产：`病灶标注`、`分级`、`图像`、`区域`、`文本`、`配对` | 按主键 **upsert**，带审计列 | Gold 构建脚本、复核人员 |
| **Gold** | `gold/` | 评测与决策专用：`检索任务`、`相关性判断`、`证据卡样本`、`决策动作标注` | **全量重建**，带冻结版本号 | 模型训练、评测、Demo |

**铁律**：
1. Bronze 永不修改。任何清洗都产出到 Silver，原始件保持字节级不变（SHA256 可验）。
2. Gold **绝不**直接读 Bronze。Gold 只从 Silver 构建。
3. 评测集一旦冻结（`frozen_at` 非空），Gold 该分区**禁止任何写入**，由校验脚本强制。

## 1. 命名与编码规范

| 项 | 规范 | v0.6 的问题 |
|---|---|---|
| 主键格式 | `{实体缩写}_{来源}_{6位序号}`，如 `CASE_IDRiD_000001`、`IMG_IDRiD_000001` | v0.6 用中文前缀（`病例_IDRiD_001`），跨语言处理与 SQL 兼容性差 |
| 字段名 | **英文 snake_case 为准**，中文名为显示别名 | v0.6 以中文为唯一字段名，导出 CSV 后下游全中文，不便编程 |
| 枚举值 | **英文枚举码为准**（`OD`/`OS`/`OU`/`UNKNOWN`），中文为显示映射 | v0.6 直接用中文值（"右眼"/"待复核"），编码混乱 |
| 时间 | 一律 ISO 8601 带时区：`2026-10-13T21:55:00+08:00` | v0.6 仅日期字符串 |
| 路径 | 相对数据集根目录，正斜杠 `/` | ✅ v0.5.0 已修正，沿用 |
| 版本号 | 语义化 `v{major}.{minor}.{patch}`，写在**每条记录**里 | v0.6 只写在一处 |

> **为什么要改成英文枚举**：`眼别 = "右眼"` 在 CSV → JSON → SQLite → Python 之间来回转换时，编码与大小写极易出错；`OD/OS` 是眼科国际通用缩写，同时也是打印在报告上的原文，双重收益。

## 2. 通用审计列（**所有 Silver / Gold 表强制包含**）

| 字段名 | 中文名 | 类型 | 可空 | 说明 |
|---|---|---|---|---|
| `created_at` | 创建时间 | timestamp | 否 | 首次写入时间 |
| `updated_at` | 更新时间 | timestamp | 否 | 最后修改时间；每次 upsert 必刷 |
| `deleted_at` | 删除时间 | timestamp | **是** | **软删除**。非空表示已逻辑删除，Gold 必须过滤 |
| `source_system` | 来源系统 | string | 否 | 官方来源系统，如 `IDRiD` / `文献` / `人工` |
| `provenance_tier` | 行级来源等级 | enum | 否 | **本行「实体」**的来源等级 `T1`–`T4`（字段级等级见 §2.1） |
| `official_source` | 官方出处 | string | 否 | 官方文件名，格式 `OAn:文件名`；官方不提供填 `NONE` |
| `official_locator` | 官方定位键 | string | 否 | **官方文件内的业务键**，如 `ImageNo=IDRiD_055`；不用行号（行号会随官方文件版本失效） |
| `transform` | 变换说明 | string | 否 | 官方值 → 本地值经过什么（`identity` / `ODx/4288` / `mask_connected_components` …） |
| `intermediate_source` | 中间表留痕 | string | 是 | 团队中间表 `表名:row:N`（**二级审计用，非官方出处**） |
| `record_hash` | 记录哈希 | string(64) | 否 | 业务字段拼接的 SHA256，用于幂等去重 |
| `quality_score` | 数据质量分 | float(0—1) | 否 | 该行质量分，由质量规则脚本计算 |
| `review_status` | 复核状态 | enum | 否 | `DRAFT`/`PENDING`/`APPROVED`/`ARBITRATION`/`REJECTED` |
| `data_version` | 数据版本 | string | 否 | 写入时的数据集版本 |

> **要点**：`record_hash` 是幂等性的技术保证——重跑时同一条记录哈希不变即跳过，不会产生重复行。
>
> ⚠️ **v2.2.0 变更**：原 `source_file` / `source_locator` 两列**已被上面五列取代**。
> 原因：它们的值原先指向团队自造的中间表（如 `病例.csv:row:2`），与 `source_system=IDRiD` **自相矛盾**——官方根本不存在叫「病例.csv」的文件，**溯源链在第一环就断**。旧值未丢弃，降级保留在 `intermediate_source`。

### 2.1 字段来源分级（Provenance Tier）

**来源等级是「字段级」属性，不是「行级」**——同一行里 `width`（官方论文载明）是 T1、`quality_label`（官方不提供）是 T4。因此：

- **行级** `provenance_tier` 只回答一个问题：**本行实体的来源等级**（这个实体是不是官方数据里本来就有的）；
- **字段级**等级的唯一权威定义在 `_quality/字段来源分级表.csv`（由 `_quality/provenance_map.yaml` 渲染，含 105 个字段），体检脚本会**自动核对是否有业务字段漏登**。

| 等级 | 名称 | 判据 | 可信度 |
|---|---|---|---|
| **T1** | 官方直取 | 官方文件里有**同义字段**，值 = 原文照搬（仅格式转换） | ★★★★★ |
| **T2** | 官方派生 | 官方数据 + **确定性可复现算法**（如 `ODx/4288`、掩膜像素计数） | ★★★★ |
| **T3** | 规则派生 | **非官方标准**的自定规则（如面积分段阈值） | ★★★ |
| **T4** | 合成/外部 | 规则生成文本、文献抽取、官方不提供的标注 | ★★ |

**实测分布（105 字段）**：T1 = 12 · T2 = 36 · T3 = 20 · T4 = 37；**可锚定到官方（T1+T2）= 48 个（45.7%）**。

> **诚实边界**：官方只提供 6 类资产，本地有 105 个字段，**大部分字段原理上无法官方化**（严重度、患者标识、质量标签、合成文本）。
> 「更有说服力」的本质不是「全部官方」，而是**每个字段都能回答：它从哪来、经过什么、有多可信**。

| `dme_grade` | DME 分级 | int | 是 | **0—2**，DME 风险分级 |

### 3.4 `silver_lesion` 病灶标注表（原「医学标注」）

| 字段名 | 中文名 | 类型 | 可空 | 允许值 / 规则 |
|---|---|---|---|---|
| `annotation_id` | 标注编号 | string | 否 | PK |
| `case_id` / `image_id` / `region_id` | 关联编号 | string | 否/否/是 | FK |
| `text_id` | 文本编号 | string | 是 | **v0.6 为 not_null 是错的**——强绑文本造成"无文本即无标注"，应允许为空 |
| `lesion_type` | 病灶类型 | enum | 否 | `MA`/`HE`/`EX`/`SE`/`DRUSEN`/`IRF`/`SRF`/`OTHER`/`UNKNOWN` |
| `location` | 位置 | enum | 否 | `MACULA`/`FOVEA`/`POSTERIOR_POLE`/`TEMPORAL`/`NASAL`/`DISC`/`OTHER`/`UNKNOWN` |
| `location_source` | **位置来源** | enum | 否 | `OFFICIAL`/`DERIVED_MASK`/`REVIEWED`/`UNKNOWN` |
| `severity` | 程度 | enum | 否 | `NONE`/`FEW`/`SCATTERED`/`MODERATE`/`MARKED`/`SEVERE`/`UNKNOWN` |
| `severity_source` | **程度来源** | enum | 否 | `OFFICIAL`/`DERIVED_AREA`/`REVIEWED`/`UNKNOWN` |
| `lesion_area_ratio` | 病灶面积占比 | float | 是 | 0—1，**推导证据，不作为程度标签** |
| `evidence_span` | 证据原文 | string | 是 | **逐字摘录，不得改写**；无来源则空 |
| `evidence_strength` | 证据强度 | enum | 否 | `DIRECT`（原文直接描述）/`INFERRED`（由掩膜推导）/`NONE` |
| `confidence` | 置信度 | float | 是 | 0—1；**自动派生项必须填，人工确认项可空** |

> **主从关系（v2.1 写死）**：`silver_lesion` 与 `silver_region` 是**一一对应的主从关系**（282 ↔ 282），不是两张可各自演化的独立表：
> - **`silver_region` = 几何真源**：`bbox` / `mask_path` / `pixel_count` / `area_ratio` **只以 region 表为准**；
> - **`silver_lesion` = 语义真源**：`severity` / `evidence_span` / `evidence_strength` / `confidence` **只以 lesion 表为准**；
> - **共有字段**（`lesion_type` / `location`）：两表**必须一致**，由体检脚本 `dataset_health.py` 的 CONSISTENCY 检查强制（当前 282/282 一致）；
> - **面积字段**：`region.area_ratio` 与 `lesion.lesion_area_ratio` **必须同值**；读面积一律走 `region.area_ratio`。
>
> 保留两表而不合并的理由：几何与语义的更新节奏、责任人和来源都不同，合并会让"掩膜重算"与"语义复核"互相污染。

### 3.6 `silver_pair` 图文配对表（**物理拆分**）

v0.6 把真实/弱/合成配对混在一张表，靠 `pair_type` 区分——**这是隐患**：任何一句 `GROUP BY` 写漏条件就会把合成数据混进评测。

v2.0 拆为两张物理隔离的表：

**`silver_pair_synthetic`（合成配对，仅训练可用）**
| 字段名 | 类型 | 规则 |
|---|---|---|
| `pair_id` | string | PK，前缀 `PAIRSYN_` |
| `image_id` / `region_id` / `text_id` | string | FK，not_null |
| `generation_rule` | string | not_null，生成规则名与版本 |
| `limitation` | string | not_null，**必须写明该配对的已知局限** |
| 其余审计列 | — | 见 §2 |

> **`region_id` 可空性按 `pair_level` 区分（v2.1 明确）**：
> - `pair_level=REGION`：`region_id` **必填**，指向具体病灶区域；
> - `pair_level=IMAGE`：`region_id` **必须为空**（图像级配对本就不对应单个区域，空是正确表达而非缺失）；
> - 体检规则：**非空的** `region_id` 必须 100% 关联到 `silver_region`（当前 282/282 通过）。

**`silver_pair_real`（真实配对，可评测）**
| 字段名 | 类型 | 规则 |
|---|---|---|
| `pair_id` | string | PK，前缀 `PAIRREAL_` |
| `image_id` / `text_id` | string | FK，not_null |
| `pair_level` | enum | `IMAGE`/`REGION` |
| `pair_source` | enum | `SAME_EXAM`（同次检查，真实配对）/`LITERATURE_LINKED`（文献关联） |
| `evidence` | string | 配对依据说明 |

### 3.7 `silver_region` 候选区域表（沿用 v0.6 结构 + 补字段）

### 4.2 `gold_relevance` 相关性判断表

| `judgment_source` | enum | **`GOLD_MASK`（按专家掩膜/官方分级自动判定，有效）/ `AUTO_RULE`（规则生成，仅演示）/ `EXPERT`（医生盲评）** |
| `judgment_rule` | string | 判定规则与阈值，可复现 |

> v0.6 的 1089 条相关性判断全部是 `AUTO_RULE`。v2.0 要求：**Gold 层主指标的判断必须来自 `GOLD_MASK` 或 `EXPERT`**，`AUTO_RULE` 只能进演示分区。

## 5. 质量规则与发布门禁

| 规则 ID | 规则 | 违反后果 |
|---|---|---|
| `IQ-S1` | `silver_image.sha256` 必须等于 Bronze 文件重算值 | 阻断发布 |
| `FK-I1` | `raw_path` 指向的文件必须存在 | 阻断发布 |
| `FK-C1/C2` | 病例的 `image_count`/`annotation_count` 必须与实际行数一致 | 阻断发布 |
| `NR-01` | 所有枚举字段不得出现值域外的字符串 | 阻断发布 |

| `DQ-01` | 任何 Silver 行 `quality_score` < 0.5 → 不得进 Gold | 阻断该行 |
| **`MT-01`** | **`gold_retrieval_query.metric_validity=VALID` 的查询，其 `query_origin` 不得为 `SYNTHETIC`** | **阻断发布** ← 防循环指标 |
| **`MT-02`** | **文本查图像主指标只统计 `query_origin ∈ {REAL, LITERATURE}` 的查询** | **阻断发布** |
| `FR-01` | `frozen_at` 非空的 Gold 分区不得有任何写入 | 阻断发布 |

> `MT-01` / `MT-02` 是本次重写最重要的两条规则——它们把"指标循环"这个致命问题**从口头提醒变成了可执行门禁**。

## 6. 空值策略（显式，不依赖隐式传播）

| 场景 | 策略 | 禁止做法 |
|---|---|---|
| 眼别未知 | 填 `UNKNOWN` + `eye_source=UNKNOWN` | 禁止用 `OD`/`OS` 之一填充 |
| 部位未知 | 填 `UNKNOWN` + `location_source=UNKNOWN` | 禁止"默认黄斑区" |
| 程度未知 | 填 `UNKNOWN` | **禁止用面积占比冒充程度** |
| 文本缺失 | `text_id` 留空，标注仍有效 | 禁止为凑配对而留空又当作有 |
| 分级缺失 | `dr_grade` 留空 | 禁止填 0（0 有明确含义："无病变"，与"未知"不同） |
| 许可证未知 | `license=UNKNOWN` + 两个 `license_*` 布尔位 = `false` | 禁止默认允许展示 |
| 患者键缺失 | `patient_key=UNKNOWN` | 禁止用图像序号伪造患者号 |

**"未知 ≠ 阴性"是本数据集的最高原则**——v0.6 的标注手册已写到这一点，v2.0 把它落实为字段级约束。
