# 眼维：研究定位与技术算法优化实施方案

日期：2026年10月20日。用途：导师讨论、研究选题、算法复现、竞赛迭代与交付规划。

## 1. 总体判断

眼维已具备可运行的眼底图文检索 Demo 基础，现有前端、Nexent、MCP、OCR、图文召回、规则决策、证据卡和反馈记录值得继续保留。当前阶段不需要推倒重来，也不建议优先购买服务器、训练通用大模型或全面重写界面。

但“工程链路跑通”“完整符合赛题”“取得科研效果”“改善临床工作”是四个不同结论。目前已有第一项的工程证据，其余需要补足实现、评测与真实用户验证。

建议主线：**面向眼科教学与临床科研的低资源多模态病例检索与证据复核**。在明确的一个任务上证明效果，再逐步扩展。

本文整合此前研究、技术和前端建议，并依据当前源码纠正一处描述：**现有检索已经包含 BM25 与 FLAIR 语义召回的加权排名融合，不能把“增加RRF”当作从零新增能力或原创算法。** 后续应对现有融合建立严格基线，研究分离多路召回、可靠性加权、冲突重排与主动追问的增益。

本轮只生成规划文档，没有新增算法实现、修改线上行为或重新执行实验。下文的实验、指标与验收项均为计划，历史观测另行标明。

## 4. 研究定位与真实用户价值

### 4.1 建议定位

产品表述：**眼维——面向眼科教学与临床科研的多模态病例检索及证据复核系统。**

主研究问题：在样本和标注有限、查询信息缺失或存在冲突的条件下，如何结合领域约束、多模态召回与主动追问，提高相关病例查找的可靠性和可解释性？

眼科图文检索与多模态基础模型已有公开研究，例如EyeCLIP与眼底FLAIR[2][3]。因此，仅接入模型并返回相似图像不宜声称算法创新。原创贡献需要由明确方法、对照实验和可复现结果支持。

### 4.2 优先选择一个主场景

| 场景 | 目标任务 | 当前适配程度 |
|---|---|---|
| 眼科教学与病例复核 | 找到相关参考病例，观察相似点、差异和来源 | 最接近当前能力，可作为首个用户验证场景 |
| 临床科研病例筛选 | 根据条件从授权历史资料中筛选病例 | 适合作为主线，需要真实资料关联与索引 |
| 会诊资料整理 | 汇集病历、检查、影像和关键证据 | 可逐步扩展，需多文件处理 |
| 自动筛查、诊断与转诊 | 识别患者风险并决定后续诊疗 | 当前证据不足，不作为第一阶段承诺 |

WHO强调糖尿病视网膜病变筛查应衔接进一步检查和治疗[4]。相关病例检索可以成为辅助工具，但不能据此认定已解决完整筛查或转诊问题。

### 4.3 真实需求验证

请导师协助访谈眼科医生、教学人员或科研人员，记录他们如何找病例、使用哪些系统、耗时在哪、什么结果才算可用。访谈数量可以先小规模起步，但不预先宣称代表所有医院。

根据访谈制定相同的查找任务，比较人工查找、基础检索和眼维，记录完成时间、相关病例召回、关键证据遗漏、错误与人工修正。医生认可与医学有效性应建立在真实参与和记录之上，不能由模型代替医生评价。

## 5. 数据与评测：所有算法优化的前置工作

### 5.1 数据治理

1. 核对图片来源、许可、文件hash、标签来源、原始掩膜与衍生字段。
2. 分开人工确认、自动推断、合成描述和待复核内容，不能以同一可信度参与解释。
3. 按患者或原始影像分组划分；如果没有患者ID，采用可取得的最严格分组并披露不足。
4. 同图不同区域、近重复影像、同病例多次检查的泄漏风险分别检查。
5. 脱敏授权后使用真实资料，患者数据不进入公开仓库。

### 5.2 当前gold数据特别问题

当前查询含SYNTHETIC、DEMO_ONLY，相关性存在AUTO_RULE判断。某些规则以“同一图像区域”作为EXACT、以“另一图像同病灶区域”作为DISSIMILAR，测到的可能是源区域找回，而非医学相似性。

因此要区分两个任务：

- 源区域找回：用于工程与索引验证，按现有自动gold解释，不包装为临床病例相关性。
- 相似病例查找：由明确相关性准则和人工复核支持，允许多个相关答案。

五维相同表示当前表示存在歧义，不应推导为所有算法都有相同的普遍“信息论上限”。

### 5.3 指标与实验纪律

| 评测对象 | 建议记录 |
|---|---|
| 检索 | Recall@K、MRR、nDCG@K；明确检索单元是图片、区域还是病例 |
| 冲突和追问 | 冲突发现、正确追问、无效追问、达到可用结果所需轮次 |
| 返回与拒答 | 不同阈值下的覆盖率、错误返回率；单独列出失败案例 |
| OCR | 眼别、否定、病灶、位置、数字等关键字段准确性及人工修正量 |
| 用户任务 | 查找时间、资料遗漏、复核负担与任务完成情况 |
| 性能 | 冷启动、热运行、排队、模型首响应、工具、结果可用、最终完成和失败 |

开发集调参，测试集只用于最终比较；方法之间使用相同候选库、过滤、去重和检索预算。处理并列分数采用固定且可复现的规则。缺失标注与未判断候选不得直接声称医学不相关，需说明口径。

## 6. 技术与算法优化路线

### A0：冻结现有基线

保存源码、配置、模型与索引版本、数据hash、查询集、随机种子和原始排名。当前在线混合检索已经有基于排名的融合；不要重复开发后称其为全新方法。

基线至少包含：BM25；FLAIR文字到图像；现有融合；现有融合加五维重排。查询有图和无图分别统计。评测工具应明确记录语义编码是否实际执行，不能在模型不可用或冷加载降级时仍标为完整图文方法。

### A1：分离召回与可靠性加权融合

**现有位置：** `02_代码/yanwei/multimodal.py`的`recall`，及`mcp_tools.py`的`search_cases`。

现有`recall`可先固定权重混合图片和文字向量；随后与BM25进行加权排名融合。实验版本可将BM25、FLAIR文字、FLAIR图片保留为独立排名，再融合比较。

RRF基本形式：`score(d) = Σ w_j / (k + rank_j(d))`；缺席某一路的候选贡献为零。RRF为已有公开方法[5]，作为复现和对照，不声称原创。

建议顺序：等权RRF→固定权重RRF→基于输入可靠性的权重。可靠性可以参考图片质量、文字是否完整和模态可用性；不得用测试集标签决定单次权重。k和权重只在开发集确定。

**验收：** 同一候选单元、同一去重与过滤规则、相同Top-K预算下比较；保留每一路排名和最终贡献。某一路不可用时明确降级。没有显著或一致收益时保留简单基线。

**代价：** 独立图文编码可能增加耗时；文本模板与图片向量可按模型/预处理版本缓存。图像级结果映射至区域级时必须明确聚合规则，避免一图多区域导致虚假的排名优势。

### A2：冲突感知重排序

在现有五维一致性基础上区分：明确匹配、明确冲突、未知、否定、不确定和标签未复核。

以视觉/文字召回分、字段匹配、冲突数量、来源可信度作为可解释特征。先做固定规则和消融；有足够人工相关性标注后，再试轻量学习排序或成对排序。任何“硬排除”都应以信息可靠且符合任务定义为前提，避免OCR错字导致错杀。

典型测试：未见出血≠出血；未填写眼别≠左右眼冲突；疑似病灶不等于确诊；自动推断标签不等于人工确认。

**验收：** 在相关性排序改善之外，同时记录误排除、冲突漏检和无结果情况。人工相关性标注与从相同字段自动生成的评分规则分开，避免循环证明。

### A3：有价值的主动追问

把“缺字段就问”作为基线，研究“哪个问题最能区分当前候选”。可以从候选字段分布出发，计算预期不确定性减少，同时考虑问题可回答性和用户负担。

先用透明规则实现，再考虑信息增益近似。候选分数不是天然概率，不能直接当作校准后的后验。用户回复未知时不得擅自补值。

**验收：** 相同任务比较固定追问与主动追问的检索质量、轮数和无效问题。离线自动模拟用户只能作为预实验，真实用户交互需要独立报告。

### A4：整图与局部区域联合检索

整图向量可能弱化微小病灶信号。首先比较整图、人工指定区域或多尺度裁剪，再研究自动定位，不急于重训分割模型。

建立局部向量与原图坐标映射，明确区域聚合及病例去重。参考库既有掩膜和上传图像上的预测区域必须区别展示。FLAIR整图预训练模型用于裁剪区域未必有效，需要实测。

**验收：** 独立查询与相关性标注下对比召回、误匹配和编码耗时。训练或测试时使用专家掩膜选区应明确是否属于oracle条件，不能冒充自动定位效果。

### A5：拒答、覆盖范围与校准

现有“证据充分性”属于规则分，不等于正确概率。结合候选分数与差距、字段冲突、图片质量、标签可信度和库覆盖范围，研究返回、追问、拒答策略。

先在独立验证集确定阈值，观察覆盖率与错误率取舍；加入库外疾病、非眼底图、模糊图和无匹配查询。相似度低或第一第二名差距小都不能单独作为通用拒答依据。

若后续有明确定义的分类输出和足够标注，可考虑温度缩放等校准方法[6]。不把规则综合分随意转换成医学概率。

### A6：经过审核的反馈更新

现有反馈落库可继续保留。新增审核队列、结构化纠错、发布候选、离线评测和版本回滚。

更新对象优先为术语映射、元数据和轻量排序参数。匿名用户反馈不直接改变线上模型或医学规则。固定验证集比较新旧版本，无收益或发生回归就不发布。

**验收：** 展示一次从真实反馈到审核、版本变更、实验比较、发布/拒绝发布的完整过程。反馈数量不等同于进化效果。

## 7. 知识图谱与Nexent工作流

图谱首先服务实际查证，而非只为比赛展示图形。最小实体包括病例、检查、图像、病灶、解剖位置、文档片段、术语和规范条目；每项带来源、审核状态、时间和版本。

最小真实查证路径：已确认病历描述→对应检查→关联影像→已复核病灶/位置→满足约束的参考病例。关系由存储与工具查询支持，不能由语言模型即兴编造。

本体半自动更新：模型或规则提出候选实体/关系→检查重复与矛盾→人工审核→发布版本→可回滚。规范对齐只引用真实、可取得且允许使用的条款，记录适用范围与版本。

通过Nexent实际支持的机制落地三个工作流模板：

1. 病历导入、OCR与人工核对。
2. 多路检索、冲突检查、主动追问与证据复核。
3. 反馈收集、管理员审核、离线版本验证。

模板应交付输入输出契约、工具schema、执行配置、状态转换、失败出口和回归样例。Nexent可保留实际编排参与，不将所有流程绕到本地程序后只保留平台名称。

## 8. 前端与产品流程

保留现有三栏和深色风格，优先改善信息结构，不做全量重写。建议用户主流程为：导入资料→对照核对→确认条件→比较候选→检查证据→反馈。

| 当前改善点 | 具体做法 | 验收 |
|---|---|---|
| 病历核对 | 左原图、右识别文字/字段；突出眼别、数字与否定；保留修改记录 | 可定位原文并修正，不确认不检索 |
| 查询入口 | 明确区分病历资料与眼底图；注明文件与当前病例的关系 | 用户不必学习工具名或配置 |
| 结果重复 | 中间突出原图及候选比较；右栏简明结论、冲突与复核 | 同一长结果不重复出现 |
| 工程术语偏多 | RETURN_CASES改为“找到参考病例”；Trace、路径、工具数移至详情 | 普通用户无需了解实现细节 |
| 可读性 | 修复Markdown符号裸露；安全渲染；提高正文和重要说明对比度 | 不能把模型文本直接当可信HTML |
| 等待与失败 | 展示实际识别/检索/整理阶段，提供取消；明确重试与降级 | 无伪造进度百分比或假成功 |
| 可解释结果 | 显示匹配/冲突/未知字段及出处，展开真实证据路径 | 得分不标成疾病概率 |
| 区域展示 | 原图、参考库标注、自动预测使用不同标识 | 不混淆参考病例区域与用户图像病灶 |

桌面常用分辨率、浏览器缩放、键盘操作和移动折叠需分别验收。普通用户仍不提供Nexent模型、工具或智能体配置入口。

## 9. 私有资料与交付技术

“上传病历作为本轮查询”与“导入自己的长期病例库”应独立定义。若选择后者，需增加病例/检查标识、多文件关联、私有索引、更新与删除，以及跨用户隔离验证。公开研究库和私有库不能默认混合召回。

新增PDF、多页和表格支持时，保留页码、区域坐标与字段来源，先设置明确的支持范围。复杂手写或无法识别内容应允许人工输入，而非无依据补全。

比赛交付要包含脱敏智能体配置、工具定义、提示词、依赖版本、数据/模型清单、许可证、启动与复现脚本。API密钥和个人资料不随包分发。新机器模型服务配置可由团队完成，不能承诺包含授权密钥的“全自动复制”。

当前没有服务器或域名。公网部署为后续可选工作，本地压缩包与公网体验网址属于不同交付物。先完成另一台干净机器的全流程验收，再宣称可移植完成。

## 10. 性能优化

已有少量热运行观测：普通查询约7.6—8.8秒；一次左右眼冲突流程约44.3秒，工具约38毫秒；OCR约393毫秒，实际工具结果到达约3.7秒。这些不是稳定P95、吞吐量或本次复测结果。

先分段计时再优化：排队、模型首响应、工具调用、编码、检索、重排、结构化结果到达、最终文本完成。重点避免重复工具调用与不必要的长上下文；结果可以在实际工具完成后优先展示。

保留离线索引、模型常驻和带版本的缓存。81张索引图的规模下不优先引入复杂向量集群。仅在资源允许时开展有限并发测试，不对当前共享服务无边界压测。任何提速都同时验证微小病灶信息和结果质量。

## 11. 分阶段实施与里程碑

按验收门槛推进，不预先承诺未经估算的工期。

| 阶段 | 工作 | 交付物与进入下一阶段条件 |
|---|---|---|
| M0 基线与任务冻结 | 用户访谈、任务定义、数据复核、版本固化 | 数据清单、可信度标识、评测协议、固定查询与原始排名 |
| M1 召回复现 | 复现BM25、FLAIR、现有融合、分离多路RRF | 可运行脚本、配置、逐查询结果；如实报告无提升 |
| M2 约束与追问 | 冲突重排、主动追问及消融 | 失败案例集、质量与轮次比较；可决定是否接入线上 |
| M3 图谱与局部实验 | 最小图谱查证、Skills模板、局部检索实验 | 一条真实多跳证据链；局部方案收益与代价 |
| M4 反馈更新 | 审核、版本、固定验证集、回滚 | 完整更新演示和新旧版本对比 |
| M5 用户与交付 | 界面改进、真实用户任务、干净机器复现 | 可验收交付包、正式Word、示例与演示材料 |

M3中的图谱最小实现可与M1/M2并行推进，但算法收益仍需统一评测，避免多个组件同时修改而无法归因。每次实验形成结论后，再决定保留或撤销。

暂缓事项：通用大模型训练、复杂微服务重构、大型向量数据库、全量前端重写、同时覆盖多个医疗专科，以及未验证诊断效果的宣传。若后续做多行业迁移附加验证，先沉淀稳定模板，再做小规模独立实验。

## 12. 第一轮复现的具体范围

第一轮聚焦A0/A1，不同时启动所有算法。

1. 审计现有数据与gold口径，输出实际数量、复核状态、切分和泄漏风险。
2. 固定现有配置，明确当前已有的排名融合逻辑。
3. 搭建与生产服务隔离的实验入口，避免修改Nexent发布版或占用其请求上下文。
4. 对同一查询比较BM25、实际执行的FLAIR文字召回、现有融合、分离后融合。
5. 图片查询单独评测；图像本身已入库的自匹配只用于工程检查，不当作独立新图检索效果。
6. 输出JSON原始排名、Markdown结果表、配置与复现命令；未执行分支标为未执行，不填假分数。

若现有gold不足以衡量相似病例价值，第一轮结果仅作为工程复现，同时整理人工相关性标注模板。不能为了尽快出数字而沿用不匹配的临床结论。
