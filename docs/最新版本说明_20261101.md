# 眼维最新团队开发版（2026-11-01）

## 本次更新了什么

本次替换10月20日版本的应用代码，保留既有部署脚本、第三方许可与协作资料。main以本次提交为准，历史版本仍可通过Git找回。

1. 主界面保留深色风格，分成了解系统、病例检索、医生工作台。首页用示意图解释眼底图片、病历截图和文字三种输入。
2. 医生可以对本轮参考结果接受、否定、修正或标记不确定，填写依据。后端保存原始工具结果、修改内容和记录编号。
3. 复核记录可按病例、关键词和结论查询，分页查看并导出当前页。同一团队复核账户可以查询其历史记录；共享授权码不等于实名医生认证。
4. 上传显示已选择、待上传、上传成功的状态，支持JPEG、PNG、WebP、TIFF，增加拖入图片与粘贴截图入口。
5. 知识图谱基线位于research/knowledge-graph，包含输入表、构建与查询程序、独立展示页和测试。它尚未接入Nexent主链路，没有自动训练或临床有效性结论。

## 组员怎么更新

已有仓库的组员：先提交或暂存自己的修改，再执行git pull --ff-only。新组员克隆本仓库。不要把旧压缩包的代码覆盖到新代码上。

资源准备见[setup.md](setup.md)，完整部署仍从根目录START.cmd或start.sh开始。代码不包含模型权重、原始眼底图片和离线索引，需要按资源说明准备。

团队管理员在新机器首次配置Nexent与模型服务；普通访客使用团队部署好的网页，不操作Nexent后台。Git代码不能携带本机已登录状态、平台授权和模型密钥。

更新现有Docker环境需要重新构建应用镜像并重启相应服务。仅拉取源码不会替换正在运行的容器，更新前备份本机.env和04_产物。不要删除Docker数据卷。

## 医生复核初始化

管理员在仓库根目录执行：

```bash
python integration/clinical_review.py
```

会在04_产物/integration/reviewer.secret.json创建本机独立的随机团队授权码；已存在则保留。管理员在本机查看此文件并通过团队内部渠道提供给复核人员，不要提交文件或把授权码写进仓库。

访问部署地址的/doctor进入工作台，输入团队授权码。服务器复核授权长期保留，团队更换授权码会撤销原授权；浏览器清理Cookie后仍需重新授权。复核结果保存在04_产物/integration/clinical-review.sqlite，需单独备份。

旧版普通反馈入口不等于医生审核。默认从04_产物/反馈/feedback.jsonl读取；可用服务器环境变量YANWEI_LEGACY_FEEDBACK指定路径。Docker中需要管理员将旧反馈文件只读挂载到访客容器后再指定容器内路径，不上传真实反馈到Git。没有旧文件时显示空记录。

## 反馈如何进入后续迭代

保存反馈只做留痕，不会自动修改原始数据或训练模型。integration/review_release.py提供准备、审核激活、回滚的本地管理工具，需要团队提供脱敏结论和对应评测报告。当前复核说明接入位于本机开发桥dev_bridge.py；标准Docker检索服务尚未接入这一附加说明，不应声称已实现自动进化。

dev_bridge.py用于复用开发机已有检索服务，其默认地址不适用于所有机器；标准部署使用deploy/compose.yml，不需要运行该桥。

## 已验证与待验证

本次发布在Windows Python开发环境运行工程测试。它们验证业务规则、接口约束和隔离等工程行为，不等于真实模型医学效果验证，也不等于全新电脑冷启动验收。

上传接口、PNG和TIFF上传、截图OCR确认步骤此前在本机实际链路验证过。用户报告的原生文件选择弹窗问题仍待在其Edge浏览器人工确认；自动化设置文件和模拟拖放只能验证页面处理逻辑，不能证明用户弹窗已恢复。

尚未提供公网部署、个人病例库、PDF多页导入、真实实名医生权限、经过临床验证的诊断能力。当前定位为教学与科研参考病例检索原型。
